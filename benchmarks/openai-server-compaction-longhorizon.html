Codegraff compaction experiment · 2026-08-12

OpenAI server compaction survived the horizon. It did not win this run.

A paired live run used the same experimental binary, model, 12-step chained task, token facts, and forced-low 4% threshold. Automatic OpenAI compaction completed the task after pruning 52 earlier history items. Local prose compaction also completed it—and happened to use fewer calls, fewer total tokens, and less wall time.

What happened

The server boundary worked as designed

  1. This early experiment asked the Responses stream for automatic compaction at 4% of the model's 272k window; the released mechanism instead calls /responses/compact explicitly at the guarded threshold.
  2. The service emitted a real encrypted compaction output item during the chained workflow.
  3. The experiment originally retained only the newest opaque item. Follow-up controlled replay found that insufficient, so v0.0.250 transactionally installs the endpoint's complete canonical output array and resets its token anchors.
  4. The agent then completed the remaining chained steps and returned all 12 authoritative facts correctly.

Request directive: src/agent_server_compact.zig:111-130. Safe history replacement: src/agent_server_compact.zig:132-189. Near-limit local fallback: src/agent_server_compact.zig:192-212.

Long-horizon method

A sequential workflow that must cross compaction

  • The fixture generated 12 one-time token facts and a randomized chain. Each probe reveals only the next step, preventing batching.
  • Each step emitted 26 filler lines below the tool-result spill threshold, forcing context to accumulate.
  • Both arms used the same binary, model, seed, task, credentials source, context threshold, and maximum-call budget. Only GRAFF_SERVER_COMPACT=1 versus 0 changed.
  • The server arm used one prune and no local summaries. The local arm completed two summaries; five additional summary attempts encountered transient OpenAI overload errors and safely preserved history.
Cold-recall appendix: the local arm returned 12/12 in its fresh process. The server arm's first fresh-process request was rejected as overloaded before any model call; a later retry returned 12/12. Both agents had deliberately written the facts to disk, and the harness also leaves captured stdout in the task directory, so cold recall demonstrates recoverability—not compaction fidelity.
Interpretation

Useful proof, not a ship/no-ship verdict

Proven

Continuity

The automatic service item was ingested, old history was actually removed, the Responses chain re-anchored, and the task still finished perfectly.

Not proven

Efficiency win

The arms took different action strategies, and n=1 cannot separate compaction policy from ordinary model nondeterminism.

Decision

Keep it gated

Continue as an OpenAI/Codex-only experiment with local fallback; do not generalize it to other providers.

The earlier fixed coding-context benchmark found server compaction cheaper than local summaries. This longer agentic run found the opposite observed totals. Together they suggest server compaction is sensitive to workload shape and to the post-compaction action policy. A causal follow-up should replay a scripted sequence of identical tool calls across both arms and repeat each arm several times.
