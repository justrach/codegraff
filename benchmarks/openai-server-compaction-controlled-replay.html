Controlled method

The fixture and exact probe stayed frozen

  • Fixture: 175,308 bytes, 40 Responses items, 14 function calls, 14 exactly paired outputs, and ten planted facts read from tool results.
  • Canonical message SHA-256: 227e22af1daf667a591a958467e4236b1cbb487799bec8af1a72a56d4cee2aef.
  • Fixed server arm: resume the fixture in the revised binary, trigger automatic OpenAI compaction, require a saved compaction_summary, then ask the no-tools ten-line probe.
  • Local arm: resume the same fixture, invoke the real JSON {"type":"compact"} control, then ask the identical probe.
  • Trial order alternated server→local, local→server, server→local. All six final arms completed with zero recorded API errors.

Official OpenAI Platform path

Implementation guardrails

The experiment now fails safe

Provider boundary

Exact first-party gate

Server compaction requires both kind == responses and id == codex. A Responses-compatible gateway remains disabled even under the force-on override.

Lifecycle coverage

Fresh and resumed sessions

In-turn, between-turn, and restored-session automatic compaction all route through the server policy. Resume still never authorizes destructive trimming on failure.

Failure behavior

Original history survives

Invalid endpoint responses do not mutate messages or token anchors. The REPL/JSON stream reports the fallback, then the existing local compactor runs.

No in-stream ambiguity

One owner

The Responses request no longer emits context_management; automatic compaction is one explicit standalone transaction.
