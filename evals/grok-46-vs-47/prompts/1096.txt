PR 1096 — fix(native): require visible composer selection on Enter.

Bug: the @ menu defaults its active index to the attachment action. The keyboard handler activates that row on Enter or Tab immediately, even though `engaged` intentionally withholds the visual highlight until the user hovers or navigates with the arrow keys. Pressing Enter after typing an @ query can open the system file picker with no visible selection.

Required behavior:
- An autocomplete row is keyboard-activatable only after it is visibly engaged (hover or arrow keys).
- If the @ menu is open but no row is engaged, Enter still submits the prompt and Tab keeps normal focus traversal.
- Reuse the existing `engaged` state. Do not add a second selection model.
- Shift+Enter must not activate a row.
- Arrow keys are not activation keys.
