# Codegraff v0.0.297

This update improves tool responsiveness, clipboard image pasting, PR verification, and coordination between sessions.

## Tools keep moving while MCP connects

A slow MCP handshake no longer holds up the second model request. Finished connections become available on later requests while native tools continue running. Explicit MCP inspection and shutdown can still wait for pending connections. (#860)

## Clearer GUI turn endings

The desktop bridge preserves the agent’s final reply and completed tool results when a turn encounters an error. Agent errors no longer break the response stream and appear as a generic browser network error. Completed turns remain finished, Stop remains stopped, and genuine interruptions explain that completed tool results are kept. A lost connection still requires a follow-up; this does not verify the generated app or automatically replay work.

## Elapsed work and draggable chat tabs

Live turns display “Working for” with minutes and seconds; finished turns show
“Worked for” with a frozen duration. Long silences still show when the last
update arrived. Saved snapshots continue to distinguish unknown live status.

Drag tabs to reorder them, or drop one at a chat edge to split the view. Existing
conversations and drafts move with the tab. Horizontal and vertical splits can
be combined within the same group, with a four-pane limit.
Escape cancels a drag. A floating tab follows your pointer, the destination shows
where it will land, and panes settle smoothly into place—including stacked views
when you drop below. Reduced-motion preferences are respected.

Split chats share one combined workspace tab, with individual names and close
buttons inside their panes. Switching tabs restores each group's layout and
focused chat. New tabs leave existing splits intact; the split toggle separates
the group back into individual tabs.

## Bounded regression checks

Desktop checks have an external watchdog, so a frozen test process cannot stop
its own deadline. Runtime fixture timeouts also terminate the owned process
group on macOS and Linux, preventing inherited output pipes from keeping failed
tests open. Compiled-test discovery avoids the expensive pattern scan and skips
generated dependency trees.

## Cleaner completion text

Search citation control markers are removed from streamed completion text, including markers split across response chunks. Surrounding text and ordinary Unicode remain intact. (#819)

## More reliable image pasting on macOS

Clipboard images are read directly through AppKit instead of relying on PNG coercion. PNG, TIFF, JPEG, PDF, and copied image files are exported to a temporary PNG. Conversion and access failures are distinguished from a clipboard with no image. Reads are bounded, and a clipboard change during extraction gets one retry. (#843)

## PR publication and completion checks

Non-draft publication gathers fresh head evidence for each attempt. Failed lookups, malformed responses, and incomplete check data remain unresolved. Body files are read for verification text; quoted text cannot masquerade as a draft flag. An explicitly selected remote head is checked separately from the current local checkout. (#847)

Publishing a PR creates a verification obligation that survives session saves and resumes. Completing todos or repeating `attempt_completion` cannot replace passing checks on the current PR head. Unpushed local changes cannot borrow the previous head's passing CI. A draft can be handed off with an explicit unverified label. (#853)

These checks apply to recognized GitHub CLI commands issued through the harness. Dynamic or compound publication commands must be separated into literal commands. CI results verify check outcomes; the wording review remains a heuristic and does not prove every behavioral claim in a PR description. Fork-qualified heads that cannot be resolved remain draft-only.

## Durable peer handoffs

Claim changes are serialized and written atomically. Each check reloads the current ledger, so a handoff enables the receiver and revokes the previous owner's publication access. Bash rechecks claims at its execution boundary, including RLM calls. Independent branch claims remain separate when the command target can be resolved. Unknown process identity does not expire ownership. (#840)

Claims coordinate sessions sharing a workspace ledger. They are not a general lock against commands run outside the harness, and ambiguous command targets are checked conservatively.

## Legacy server cleanup and port checks

`servers list` identifies suspected orphan listeners and, where their identity can be verified, shows an explicit `stop-suspect` command. Its token binds the selected process start and executable. The stop path rechecks identity and group membership before signalling, including escalation. Suspects are never silently adopted or automatically stopped. (#817)

Port preflight checks cover IPv4 and IPv6 listeners on the same numeric port. The check cannot reserve the socket or eliminate a later bind race, and unsupported shell launch forms remain outside its coverage. Automatic cleanup preserves listening servers when browser visibility is unknown.

### Mixed split layouts

- Combine left/right and above/below splits in one tab, with up to four chats.
- Resize each branch independently; returning to a tab restores its layout.
- Smoother dragging with less repeated rendering work and cleanup of closed-chat state.
- Bounded front-end stress checks cover repeated opening, closing, dragging and resizing.

## Lighter large conversations

Large saved code conversations initially render a bounded recent section. Earlier
messages remain available through “Show earlier messages,” with the reading
position preserved. Long live conversations use the same limit while following
the latest reply. This reduces initial rendering work without changing saved history.

Growing content keeps following the latest reply until you scroll away. Refreshing
a snapshot that has become shorter keeps its remaining messages visible.

Long completed code blocks show a highlighted preview with an option to reveal
every line. Copy still includes the entire code block, and file previews remain
fully expanded. Shared theme tracking reduces repeated work when switching
between light and dark mode.

## HTML explanations inside chat

Graff can use the desktop `create_html` tool to show a saved HTML/CSS explanation
inside its reply. Preview, inspect or copy the original source, and reopen the
result from saved conversations. Native expandable sections work; scripts and
external resources are disabled. Hidden and offscreen previews release their
embedded views. This feature does not enable telemetry uploads.

## Open projects from your terminal

Install the `codegraff` command from the desktop Tools menu. Run `codegraff .`
or pass a folder to open that project, including when the GUI is already running.
Passing a file opens its parent project and displays the file in Files. Existing
chats keep their original folders, and reopening the current folder reuses its tab.

## Edit queued prompts

Queued prompts can be edited before they are sent, with image attachments shown
alongside the text. Opening an editor pauses that chat's queue until the edit is
saved or cancelled, so a finishing turn cannot send the old text while it is
being revised.

## Clearer MCP setup

A bundled guide explains how to add and use MCP servers. Optional servers named
explicitly in a project's configuration are included at startup; inherited
optional servers keep their existing opt-in behavior and trust checks.
