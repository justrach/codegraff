# v0.302.67

Claude Agent keeps a tool load from ending the turn, and a finished task still hears a peer who writes to it directly.

- **A tool load no longer drops the call.** When graff's tool list changed (usually `load_tool_schemas`), Claude Agent removed graff's tools from Claude Code and added them back. The call that loaded the tool was still open, so Claude Code failed it with "Connection closed", and the model often stopped there or got "No such tool available" for the tool it had just loaded. graff now tells Claude Code that the list changed and keeps the connection, so the call completes and the model uses the new tool in the same turn. (#1789)
- **Peer wakes come with `peer_message` loaded.** A turn started by unread peer mail has the inbox tool ready with its first request, so it no longer spends a call loading it. On Claude Agent, that first call used to be refused and forced a fresh session. (#1789)
- **Direct messages reach a finished task.** After a task ended with `attempt_completion`, nothing could start another turn, not even a message addressed to that session. A task that ended with an ordinary answer did hear one, so whether a follow-up arrived depended on how the model happened to finish. Both now behave the same: room messages wait for your next prompt, and messages addressed to the session start a turn. (#1789)

Includes all changes from v0.302.66.
