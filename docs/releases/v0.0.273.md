# v0.0.273 (2026-08-22)

Long-running tool calls stop reading as a hang. A blocking tool call —
a build, a test suite, a `bash_output wait_ms>0` wait — used to print
one ⚙ row and then go silent for as long as the call ran; this session's
own trace caught 420s of nothing during a pre-push tier-1 run.

## Silence heartbeat

After 15 seconds without new output (then once per interval, reset by
any fresh byte) the tool prints one dim chrome line:

    · bash still running · 2m10s

Foreground `bash` gets it from `process_runner`'s existing 200ms poll
loop; watched background jobs get it from the `bash_output` wait loop.
It renders through the frontend sink on the fullscreen TUI and straight
to stdout on the line REPL; `--json` drops it, so no wire shape changes.

Deliberately NOT in this release: a cap on blocking waits. ADR 0010
measured the old poll-loop policy at 199 model hops per 203 waits — the
wait stays block-until-exit, and only the human gets narration.
