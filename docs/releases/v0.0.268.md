# v0.0.268 (2026-08-20)

This release makes subagent personas files you can actually write, and
closes the grok-build job loop that 0.0.267 started: live output, wait
for exit, then a single notify instead of a poll.

## Codex-shaped agent files

Personas used to be markdown with YAML-ish frontmatter. That still works,
and `/agents promote` still writes `<niche>.md`. You can now author the
same niche as a standalone TOML file, with the field names Codex uses:

```toml
name = "pr_explorer"
description = "Read-only codebase explorer."
model = "grok-4.6"
model_reasoning_effort = "medium"
isolation = "shared_cwd"
developer_instructions = """
Stay in exploration mode.
Cite files and symbols.
"""
```

Load order (later shadows earlier by name):

1. compiled builtins
2. `~/.codex/agents`
3. `~/.harness/agents`
4. plugin `agents/`
5. `.codex/agents`
6. `.harness/agents`
7. a verified learned policy

In one directory, `.md` loads first and `.toml` wins. Spawn is unchanged:
`subagent agent:"pr_explorer"`. Pins still resolve spawn > persona file >
session default. `sandbox_mode` is accepted so a copied Codex file loads;
only `worktree` / `shared_cwd` mean anything to graff. Codex MCP/skills
tables in the file are ignored — those stay session MCP.

Templates live in `docs/examples/agents/`.

## Live bash, then one notify

Foreground bash now emits 16 KiB `bash_output_chunk` frames the way
grok-build does. Those bytes go to a dedicated raw terminal buffer, not
the prose stream, so a `ls` does not interleave with the model's
sentence. When a background job exits, `job_notify` records a wake: the
next agent step sees it, and an idle TUI starts a turn. Combined with
ADR 0010 (wait-for-exit already in 0.0.267), the model should not poll
`bash_output` every 30s.

## Distribution

Prebuilt archives are available for Linux, macOS, and Windows on arm64 and
x86_64. Both macOS binaries are Developer ID signed, hardened-runtime enabled,
and notarized by Apple; `SHA256SUMS` covers all six platform archives.
