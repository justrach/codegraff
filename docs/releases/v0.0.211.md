# 11.4x faster one-shot runs, bounded MCP shutdown, and recipe outcomes

v0.0.211 removes the largest fixed costs from short CLI, SDK, and automation
runs. It also adds the observational data needed to compare complete agent
recipes without silently changing anyone's model, effort, or tools.

## Startup and shutdown performance

- A measured one-shot startup and exit path fell from `1.409 s +/- 0.048 s` on
  v0.0.210 to `123.4 ms +/- 3.9 ms`, an 11.42x improvement on the same machine.
- The patched core starts and exits in about 4.3 ms when the optional companion
  is absent. Remaining time in the full measurement belongs to companion
  discovery and teardown.
- Kimi's live account catalog is now lazy. Unrelated providers do not pay for a
  Kimi network request at startup, while Kimi selection, `/model`, and `/models`
  still load the current account catalog on demand.
- MCP stdio servers receive a clean EOF shutdown, followed by a bounded 100 ms
  grace period. A server that refuses to exit is force-terminated and reaped,
  preventing slow exits and orphaned processes.
- Release jobs now build the `graff` CLI directly instead of also compiling the
  standalone development REPL for every target.

## Inspectable performance receipts

- Startup traces now include structured `startup_phase` records with phase and
  cumulative milliseconds.
- Every root turn emits a `recipe_outcome` for the exact provider, model,
  reasoning effort, prompt, toolset, harness version, and coarse task class.
- Outcomes keep success, latency, model calls, tool calls, tool errors,
  uncached tokens, cache-read tokens, and estimated cost as separate objectives.
  The included Pareto comparison foundation cannot reward a cheap failure by
  collapsing everything into one score.
- Signed scores link back to local recipe metadata for later analysis.
- Recipe tracking is observational in this release. Automatic model or effort
  routing remains disabled until signed provenance, canaries, and rollback are
  in place.

## Reliability and compatibility

- Dynamic Kimi catalogs continue to expose account-enabled models such as K3,
  their live context windows, and supported thinking controls.
- Kimi credential entry refreshes the live catalog immediately.
- Existing command, model preference, SDK, transport, trace, and signed-score
  behavior remains compatible.

## Validation and distribution

- The full Zig test suite, formatting checks, build, and diff checks pass on
  Zig `0.17.0-dev.813+2153f8143`.
- Deterministic JSON controls pass all 19 cases, and saved model preference tests
  pass.
- ReleaseFast cross-builds pass for Apple silicon macOS, Intel macOS, x86_64
  Linux, arm64 Linux, x86_64 Windows, and arm64 Windows.
- Both macOS binaries are Developer ID signed and submitted to Apple's
