# v0.0.269 (2026-08-20)

This release is the image-transport fix on top of 0.0.268: screenshots
pasted into `ask_user` reach the model as pixels, and compaction can no
longer summarize those attachments away mid-turn.

## ask_user images

The clarification UI accepted screenshots and wrote `[Image]` into the
tool result. The model never saw the files (#580). Pastes now queue (up
to 16) and ride a follow-up user vision message after the text tool
result — the same blocks a normal prompt already builds. Responses and
OpenAI tool output stay text-only (ADR 0015). If markers are present and
nothing staged, the result says so and names path / paste-text /
next-prompt fallbacks.

## Compaction keeps the live prompt

Automatic compaction could put the unresolved current user message in
the summarized prefix. Text survived; image blocks did not (#581). The
cut now stops before that opening user turn. A HungRequest retry does
not move it. If the live prompt is the whole history, compact fails
with `ActivePromptPinned` instead of replacing pixels with a summary.
Traces emit `compact_cut` with the boundary and preserved image count,
not payloads.

## Distribution

Prebuilt archives are available for Linux, macOS, and Windows on arm64 and
x86_64. Both macOS binaries are Developer ID signed, hardened-runtime enabled,
and notarized by Apple; `SHA256SUMS` covers all six platform archives.
