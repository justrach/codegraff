# v0.302.74.5

Hotfix release resolving four P0 correctness issues across Claude Agent and multi-workspace tool execution.

## Highlights

- **Claude Agent unprefixed tool calls (`#1811`)**: When the model emits a bare `tool_use` name without the `mcp__graff__` prefix, Claude Code rejects it internally with `"No such tool available"` and streams a retry in the same step. `unprefixToolUse` and `turn` now classify and skip non-`mcp__graff__` `tool_use` blocks instead of breaking early on the first `message_stop` and executing the rejected call in graff's tool loop.
- **Claude Agent images across interrupted turns (`#1810`)**: `freshContent` now preserves recent `image` blocks from earlier messages and `tool_result` entries inside `<conversation-checkpoint>` as real `image` content blocks within a 4 MiB / 8-image budget, and marks any image omitted for size with `[image omitted: exceeded checkpoint size budget]` instead of a bare `[image]`.
- **`read_tool_result` across `workspace use` (`#1820`)**: Persisted `tr_N` handles are bound to their originating canonical path and explicit handle paths retain their worktree prefix, preventing `read_tool_result` from silently reading a colliding `tr_N.txt` in the newly selected workspace.
- **Subagent workspace boundary stability (`#1768`)**: `Owned.context` and `runSub` snapshot the active workspace path into `agent_cwd` at spawn time when `ctx.agent_cwd` is null, so a root `workspace create` or `workspace use` does not shift an active `shared_cwd` worker's file-tool confinement boundary.
