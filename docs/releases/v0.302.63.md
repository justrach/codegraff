# v0.302.63

Authentication errors say which credential was rejected.

- **Sign-in or API key, named.** A provider can hold a sign-in and an API key at once. When one is rejected, the error now says which: "Anthropic sign-in was rejected: sign in again (graff login anthropic)", or "Anthropic API key was rejected (<source>): replace or remove the key. Your sign-in is not affected." Before, both read "provider authentication failed: sign in again or check the API key", so a desktop client offered "Log in" even when the sign-in was fine and the key was the problem.
- **The fallback key, too.** When a plan runs out and graff switches to the API key parked behind it, and that key is then rejected, the error says so: "Anthropic plan is out of usage, and the fallback API key was rejected (<source>): replace or remove the key, or wait for the plan to reset."
- **Typed for clients.** Over ACP a rejected key carries `{"kind":"api_key_rejected","provider":"<id>"}` (v1: error data on -32603; v2: `_meta["graff/recovery"]`), so a client can show "Update key" instead of a sign-in. A rejected sign-in still carries `reauth_required` as before (ADR 0310).

Includes all changes from v0.302.62.
