## One-shots skip learn auto-init (ADR 0044 / #668)

Every graff-dev SWE task used to make exactly 5 API calls (the
`learn_auto` bootstrap floor) and then `startBackgroundLearning` copied
`.graff/learn-kit/graff-pinned` and generated suites — **38s of local
CPU per task**. Tokens and calls already matched Pi.

`startBackgroundLearning` is now a no-op on `-p` / `--json`. Interactive
REPL / TUI / ACP still auto-init after 5 model calls.
`GRAFF_LEARN_AUTO=off` still kills the whole trigger. `graff learn init`
is unchanged.

Confirm (`graff-evals/results/run-20260829-031139.jsonl`, SuperGrok
grok-4.6, `--suite swe -j 6`):

| | pass | wall | CPU | sandbox |
|---|---:|---:|---:|---:|
| before (ADR 0043) | 4/6 | 456s | 230s | 127M pin |
| after | **5/6** | **205s** | **6.5s** | 100–164K |

Wall **−55%**, CPU **−97%**, same tokens/calls (~160k / 30).
`json-stream` passed this rep (the model kept “no RS → empty”); the
earlier Pi 5/6 vs graff 4/6 was one-rep noise on the same SPEC clause
ADR 0024 already named. `label-sort` still fails — grok-build and Pi
miss it too. RSS ~91M is the process, not the pin.

Do not steal Pi's 4-tool catalog or 165M heap.

## TUI first paint no longer waits on companion MCP (#664)

Interactive `--yolo` queues `codedb-pro` onto `pending_starts` (same
defer as ADR 0035 MCP). `codedb-pro probe` is capped at 2s. A
`defer_join` fan-out that cannot `io.concurrent` skips that server
instead of inline `io.async`. Dim receipts after `plugins:` name the
next phase (`mcp: N server(s) in background`, `companion: codedb-pro
(background)`). First paint is the welcome composer.

## Mid-turn stalls stay off the transcript (#665)

(ADR 0021). A ⚠ prints only when the turn actually ends (`stream
stalled — ending turn` / `connection dropped — response ended early`).
`■ interrupted`, `↳ queued`, and `↳ force` stay.

yxlyx doctor / cube / governed / localhost stay inventory in
[yxlyx-leftovers.md](../yxlyx-leftovers.md).
