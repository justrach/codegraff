# v0.302.47

- **Compaction stops repeating when it can't make room.** When a compaction left the context still over the compaction point, the next step compacted again. A turn could spend most of an hour compacting and rereading the same files (#1686). Now the next compaction waits until the context has grown by a twentieth of the window. The server's in-stream compaction waits too. Near the 95% wall it still compacts as before.
- **The shared-tree checkpoint lets a re-issued call through.** The checkpoint remembered at most 16 acknowledged peers and never forgot one that had exited. With peers respawning, every mutating call was refused for good, and each re-issue named a different peer (#1622). One checkpoint now covers every peer live at that moment, and peers that are gone are forgotten.
- **Informational peer mail doesn't start a turn.** `peer_message send` takes `fyi: true` for a status or scope update that needs nothing from the recipient. It stays readable in the inbox but never wakes an idle session on its own. Reading the inbox no longer tells the model to reply unconditionally (#1137).
- **Shell handle failures name their cause.** A transient failure to reserve a durable shell handle is retried. If it still fails, the error says why. Only a real storage fault points at HOME's permissions (#1619).
- **Every model call start has a finish.** In `--json` mode, a request rebuilt before its response (a WebSocket reanchor, a stream reconnect, a steer) now closes the earlier attempt with `ok: false, retried: true`. A request that ends in an error closes with `ok: false` (#1665).
- Retains all changes from v0.302.46.
