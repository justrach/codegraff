# Codegraff v0.302.36

New task worktrees set themselves up from the project's `.agents/` files.

## `.agents/linked` and `.agents/prepare`

Many projects keep their agent setup in the tool-neutral `.agents/` directory,
next to `.agents/skills`. graff worktrees read only `.graff/workspace.toml`, so
such a project got no setup, and the `.env` copied into a worktree went stale
when the main checkout's copy changed.

When graff mints a task worktree (`graff worktree create`, automatic isolation,
or a workspace an ACP client asks for):

- `.agents/linked` lists repository-relative paths, one per line. Each one that
  is gitignored in the main checkout, exists there, and is missing from the new
  worktree becomes a symlink to the main checkout's copy, so a `.env` edited
  once is current everywhere. Tracked paths, `..`, globs and missing paths are
  skipped, and nothing is moved or deleted. Windows links nothing.
- `.agents/prepare` runs from the new checkout as its setup script when
  `.graff/workspace.toml` names none. Keep it fast and safe to repeat.

```
# .agents/linked
/.env
secrets/
```

```sh
#!/bin/sh
# .agents/prepare
set -eu
pnpm install --frozen-lockfile
```
