# Codegraff v0.0.302.19

Terminal authentication failures now carry typed, route-specific recovery
metadata through both ACP protocol versions. Clients can offer the matching
sign-in action without parsing error text or choosing the wrong credential
store.

ACP v1 returns `-32000` with `error.data`; ACP v2 includes the same recovery
object in the failed idle update's `graff/reauth` metadata. The object contains
only fixed route and command names. Recovery is restricted to login-sourced
credentials, and stale metadata is cleared before later requests.

Quota, server and transport failures retain their existing behavior. This
release does not add automatic sign-in, prompt replay, new device grants or
credential migration, and does not change retry or fallback policy.
