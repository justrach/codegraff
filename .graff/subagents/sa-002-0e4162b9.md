## 1. Entry Points (`lib.rs` & `main.rs`)

**`main.rs`** is a minimal 7-line launcher that prevents a console window on Windows in release builds and delegates to `codegraff_gui_lib::run()` (`gui/src-tauri/src/main.rs:4`).

  - Manages `DesktopState` (the runtime + terminal manager) and `PendingOpen` (stashes CLI argv for the frontend to drain on mount).
  - In debug builds, starts `DebugBridge` (localhost HTTP server on port 9233).
- **Invoke handler** (`L93–L180`) — registers ~45 Tauri commands from `commands.rs` plus `cg_debug_eval_result`.
- **Window event hook** (`L89–L92`) — on `Destroyed`, cancels pending follow-ups.

## 3. Runtime (`runtime/simple.rs`)

This is the core orchestrator. It bridges the Tauri frontend to the Zig-native `graff` CLI by spawning persistent `graff --json` child processes per conversation.

**Key structures** (`gui/src-tauri/src/runtime/simple.rs`):

- **`RuntimeManager`** (`L108`) — cloneable, holds:
  - `emitter: Arc<dyn UiEventEmitter>` — pushes `SessionSnapshotDto` to the frontend.
  - `projects: Arc<ProjectStore>` — SQLite registry.
  - `state: Arc<Mutex<RuntimeState>>` — in-memory conversations, workspace list, model selection, pending follow-ups.
  - `sessions: Arc<Mutex<HashMap<String, GraffSession>>>` — live child processes keyed by `conversation_id`.

- **`RuntimeState`** (`L62`) — tracks:
  - `active_workspace_path`, `active_conversation_id`
  - `conversations: HashMap<String, ConversationState>` — messages, titles, request IDs, agent IDs, plan mode, goal.
  - `selected_provider`, `selected_model`, `selected_effort`, `fast_enabled`
  - `model_catalog` — cached result of `graff --schema`
  - `pending_followups` — live `ask_user` prompts awaiting GUI answer.

- **`GraffSession`** (`L97`) — a persistent `graff --json` child:
  - `child: tokio::process::Child`
  - `stdin: Arc<Mutex<ChildStdin>>` — shared so follow-up answers can be injected while a turn is streaming.
  - `reader: Option<Lines<BufReader<ChildStdout>>>` — taken during a turn and returned after.

**Session lifecycle & protocol flow:**

1. **`send_prompt`** (`L416`) — creates a `request_id`, appends a `User` message to `ConversationState`, then calls `stream_turn`.
2. **`stream_turn`** (`L562`) — acquires session IO via `acquire_session_io`:
   - If no session exists, spawns `graff --json --yolo` (with model/agent/mode/effort/fast controls injected) via `spawn_graff_session` (`L1403`).
   - Writes a JSON line `{"type":"user","text":...}` to stdin.
   - Reads JSONL lines from stdout and maps them to DTOs:
     - `text` → `SessionMessageDto::Assistant` (appended incrementally)
     - `reasoning` → `SessionMessageDto::Reasoning`
     - `tool_call` → `SessionMessageDto::ToolStart`
     - `ask_user` → `SessionMessageDto::ToolStart` + stores `FollowupRequestDto` in `pending_followups`
     - `tool_result` → `SessionMessageDto::ToolEnd`
     - `turn` → ends the loop cleanly
     - `error` → pushes `SessionMessageDto::Error` and breaks
   - After each event, calls `emit()` which snapshots state and fires `codegraff://session-updated`.
3. **`send_control`** (`L696`) — sends non-user controls (`set_model`, `set_mode`, `compact`, `set_agent`, `set_effort`, `set_fast`) and waits for an ack JSON line.
4. **`respond_followup`** (`L943`) — writes the structured answer JSON to the session’s stdin, unblocking the streaming loop.
5. **`stop_prompt`** (`L1036`) — kills the session child (`drop_session`), which causes `stream_turn` to hit EOF and finish.
6. **Title generation** (`L355`) — first-turn titles are generated by a fire-and-forget one-shot `graff -p "<title prompt>" --yolo` call.

**Model/provider machinery:**
- `codegraff_binary()` (`L1506`) resolves the engine via a 5-step fallback: `CODEGRAFF_GUI_BINARY` env var → bundled sidecar next to exe → dev build `../../zig-out/bin/graff` → standard install paths (`~/bin/graff`, `/opt/homebrew/bin/graff`, etc.) → bare `graff` on PATH.
- `login_shell_env()` (`L1351`) — on macOS, captures the user’s login shell environment (`env` from `zsh -il`) so `OPENAI_API_KEY` etc. are visible to the GUI-spawned binary.
- `codegraff_schema_models()` (`L1427`) parses `graff --schema` JSON to populate the model picker dynamically.
- Provider auth is handled by mapping to `graff key set`, `graff login`, or direct env var detection. Credentials are deleted from macOS Keychain, `~/.simple-harness-keys.json`, and provider-specific files (`~/.codex/auth.json`, `~/.kimi/credentials/graff-oauth.json`).

**Persistence:**
- Conversations are persisted to `~/.codegraff-gui/conversations.json` (`PersistedConversation`) at turn boundaries (`persist_conversations`, `L783`).
- Prompt settings (provider, model, effort, fast) are persisted to `~/.codegraff-gui/prompt-settings.json` (`persist_prompt_settings`, `L375`).

## 4. Bridge Modules (`bridge/*`, `desktop_open.rs`, `debug_bridge.rs`)

## 6. Persistence & Terminal Handling

**Persistence (`persistence/project_store.rs`)** (`gui/src-tauri/src/persistence/project_store.rs`):

- Uses **SQLite** via `diesel` with `SqliteConnection`.
- Tables managed:
  - `opened_projects` — path, last_opened_at, display_name
  - `managed_chat_workspaces` — auto-created chat folders
  - `conversation_layouts` — layout JSON per conversation_id
  - `saved_workspaces` / `saved_workspace_layouts` — user-saved workspace layouts
- All operations are serialized through a `Mutex` (`connection_lock`) to prevent concurrent SQLite writes.
- `add_project`, `create_managed_chat_workspace`, `list_workspaces`, `archive_workspace`, `save_conversation_layout`, `create_saved_workspace`, etc.
- `ProjectStore` is initialized in `lib.rs` and stored as `Arc<ProjectStore>` inside `DesktopState`.

**Additional file-based persistence** (in `runtime/simple.rs`):
- `~/.codegraff-gui/conversations.json` — serialized `Vec<PersistedConversation>` so chats survive restarts.
- `~/.codegraff-gui/prompt-settings.json` — `PersistedPromptSettings` (model, effort, fast).

**Terminal Handling (`terminal.rs`)** (`gui/src-tauri/src/terminal.rs`):

- Uses `portable_pty` (`native_pty_system()`) to spawn real PTY sessions.
- `TerminalManager` (`L22`) holds a `HashMap<String, Arc<TerminalSession>>`.
- `TerminalSession` (`L100`) wraps:
  - `master: StdMutex<Box<dyn MasterPty>>` — PTY master fd/handle
  - `writer: StdMutex<Box<dyn Write>>` — write end
  - `killer: StdMutex<Box<dyn ChildKiller>>` — process killer
  - `exit_status: StdMutex<bool>`
- **Spawn flow** (`spawn_terminal_session`, `L172`):
  - Opens a PTY with default 80×24 or supplied cols/rows.
  - Spawns the user’s shell (`$SHELL`, default `/bin/sh`; on Windows `cmd.exe`).
  - Sets `TERM=xterm-256color`, `COLORTERM=truecolor`, `TERM_PROGRAM=codegraff-gui`.
  - For `zsh`, passes `-o NO_PROMPT_SP -o NO_PROMPT_CR` to prevent prompt spacing issues.
  - Sets `cwd` to the workspace path.
- **Reader thread** (`spawn_reader_thread`, `L216`) — reads from the PTY master in a blocking loop, batches into ~4KB chunks, converts to string via `bstr`, and emits `codegraff://terminal-output`.
- **Wait thread** (`spawn_wait_thread`, `L261`) — waits on the child process, then emits `codegraff://terminal-exit` with exit code / signal.
- Commands exposed: `terminal_open`, `terminal_write`, `terminal_resize`, `terminal_close`.

## 3 Most Load-Bearing Facts

1. **Conversation engine is a persistent `graff --json` child process.** The backend does not embed the Zig core; it shells out to the `graff` CLI, keeps one `tokio::process::Child` per conversation, and streams JSONL events over stdin/stdout. This is the central data flow for all chat (`runtime/simple.rs:1403`, `stream_turn:562`).

2. **All UI state is pushed via `TauriEventEmitter` emitting `SessionSnapshotDto`.** The frontend does not poll; the backend continuously snapshots the full `RuntimeState` (conversations, workspaces, follow-ups, active requests) and pushes it through the `codegraff://session-updated` event. Commands return the same DTO to the caller, but live streaming depends on events (`bridge/emitter.rs:12`, `runtime/simple.rs:783`).

3. **Terminal I/O is real PTY I/O via `portable_pty` with dedicated OS threads.** Each `terminal_id` gets a `spawn_terminal_session` that creates a PTY pair, spawns the shell, and runs two blocking threads (reader + process waiter) that emit output/exit events into the Tauri event bus. This is entirely separate from the `graff` child process system (`terminal.rs:172–299`).
