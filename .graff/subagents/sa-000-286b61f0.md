## Verified from GitHub issue #62

Issue #62 requests a chat-scoped `/ultracode` slash command because the existing behavior only treated the word `ultracode` inside an individual prompt as a one-turn codeword trigger; users had to repeat it every turn for sustained behavior. Source: issue body, “Problem” section, https://github.com/justrach/codegraff/issues/62.

Requested behavior:

- `/ultracode` toggles persistent ultracode mode for the current chat/conversation. Source: issue body, “Proposed behavior,” https://github.com/justrach/codegraff/issues/62.
- If currently off, `/ultracode` turns it on; if currently on, `/ultracode` turns it off. Source: issue body, “Proposed behavior,” https://github.com/justrach/codegraff/issues/62.
- While persistent mode is on, every normal user prompt in that chat should behave as if it included the existing `ultracode` codeword. Source: issue body, “Proposed behavior,” https://github.com/justrach/codegraff/issues/62.
- Existing per-prompt `ultracode` behavior must remain: a single prompt containing `ultracode` still triggers temporary ultracode when persistent mode is off. Source: issue body, “Proposed behavior” and acceptance criteria, https://github.com/justrach/codegraff/issues/62.
- Persistent mode plus an explicit `ultracode` codeword in the same prompt must not duplicate augmentation. Source: issue body, “Proposed behavior” and acceptance criteria, https://github.com/justrach/codegraff/issues/62.
- UI feedback should clearly say enabled/disabled, e.g. “Ultracode mode enabled for this chat.” / “Ultracode mode disabled for this chat.” Source: issue body, “Proposed behavior,” https://github.com/justrach/codegraff/issues/62.

## Inferred summary

The requested/added ultracode functionality is a two-layer persistence model:

- In the GUI, `/ultracode` is a chat-scoped toggle stored on the conversation and forwarded live to the active `graff --json` engine session.
- In the core engine, `set_ultracode` and REPL `/ultracode` control a session/root `ultracode_mode` flag.
- The actual augmentation remains centralized in the existing ultracode codeword branch, now guarded by `prompt contains ultracode OR ultracode_mode`, which is how the implementation avoids duplicate augmentation.

## 3 most load-bearing facts

1. The feature is explicitly chat/conversation-scoped, not global: GUI state has `ultracode_enabled` on `ConversationState`. Evidence: `460a400:gui/src-tauri/src/runtime/simple.rs:45-46`.
2. Live GUI sessions are updated without restart via JSON control `set_ultracode`. Evidence: `460a400:gui/src-tauri/src/runtime/simple.rs:1230-1235`.
3. Deduplication is achieved by reusing one core augmentation branch for either the codeword or persistent mode. Evidence: `460a400:src/main.zig:5054-5076`.
