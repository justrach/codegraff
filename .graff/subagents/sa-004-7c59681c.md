## Verified

### 1) Current checkout still has workspace/folder data, but it is `g_cwd_display`, not `folder_name`

- `src/main.zig` defines a global display string: `g_cwd_display`, documented as “Human-facing current workspace folder shown in the REPL prompt.” (`src/main.zig:2557-2560`)
- At startup, it is populated from `Io.Dir.cwd().realPath(...)`, falling back to `$PWD` or `"."`; this means it is the full cwd path, not a basename/folder-name-only value. (`src/main.zig:4573-4577`)
- The startup banner also prints it as `folder: <g_cwd_display>`. (`src/main.zig:4579-4580`)
- I found no current `folder_name` symbol via codedb (`codedb search "folder_name"` returned no results), and the current code path uses `g_cwd_display`.

### 2) Current prompt-rendering function would show the cwd if it were called

`Agent.prompt()` renders the TUI prompt. In the current checkout:

- It early-returns in JSON mode, so GUI/SDK `--json` sessions never get the human prompt. (`src/main.zig:8226-8228`)
- It computes mode/cost/cache suffixes. (`src/main.zig:8229-8242`)
- With context tokens, it prints:

  ```text
  [<model><flags> · cwd <g_cwd_display> · <tokens>k tok ...] ›
  ```

  (`src/main.zig:8243-8251`)

- Without context tokens, it prints:

  ```text
  [<model><flags> · cwd <g_cwd_display><cost>] ›
  ```

  (`src/main.zig:8252-8258`)

So the current intended prompt shape is **not** `[gpt-5.5]({folder_name})`; it is closer to:

```text
[gpt-5.5 · cwd /full/path] ›
```

or, once token metadata exists:

```text
[gpt-5.5 · cwd /full/path · 123/217k tok (56%)] ›
```

### 3) The likely bug: the main REPL loop no longer calls `root.prompt()` before reading input

In the current checkout, the REPL loop starts at `while (true)` and immediately drains steering input / reads a line:

- Current loop begins with steering-drain setup. (`src/main.zig:4904-4911`)
- It then sets `raw_line` from queued steering input, `readLine(...)`, or stdin delimiter. (`src/main.zig:4912-4923`)
- There is **no** `try root.prompt();` at the top of this loop. (`src/main.zig:4904-4923`)

The only current `root.prompt()` calls I found are inside `readLine` feedback paths after clipboard/image/drop messages:

- Clipboard-image feedback redraws by calling `root.prompt()`. (`src/main.zig:3670-3675`)
- Drag/drop image feedback redraws by calling `root.prompt()`. (`src/main.zig:3850-3855`)

That means normal interactive input can miss the model/cwd prompt entirely, even though `Agent.prompt()` still exists and contains cwd rendering.

### 4) Git history points to `1f54380` as the likely regression

Before the steering feature, the loop explicitly rendered the prompt before reading input:

- In `91a7c2e:src/main.zig`, the main loop had:

  ```zig
  while (true) {
      try root.prompt();
      const raw_line = if (interactive)
          (try readLine(...))
  ```

  (`91a7c2e:src/main.zig:4539-4544`, viewed via `git show 91a7c2e:src/main.zig | nl -ba`)

The steering commit changed that loop:

- In `1f54380:src/main.zig`, the loop begins with steering-drain code and then reads either a queued steer line or `readLine(...)`; the `try root.prompt();` line is gone. (`1f54380:src/main.zig:4774-4789`, viewed via `git show 1f54380:src/main.zig | nl -ba`)
- The commit is titled `feat: Codex-style steering — queue follow-up prompts while a turn streams`, and its diff shows the removal of `try root.prompt();` in the loop (`git show 1f54380 -- src/main.zig`, diff hunk around old loop).

So the most likely cause is: **the steering-followup change accidentally removed the normal prompt render call from the top of the REPL loop.**

### 5) Current installed/built binaries may also be behind the current checkout

In this environment:

- `./zig-out/bin/graff --version` reports `simple-harness v0.0.14-7-g782e707-dirty`.

However, `7bea7e7` also lacks the normal loop `root.prompt()` call and still has only the redraw-path calls, so the missing TUI prompt is consistent with both the installed PATH binary and the current checkout.

## Inferred

- The old UX remembered as `[gpt-5.5]({folder_name})` does not match the exact current or recent source format I verified. The verified current format would be `[gpt-5.5 · cwd <full path>] ›`, not `[gpt-5.5](folder)`.
- If a user sees no model/folder prompt at all, the likely reason is not that folder data disappeared; it is that the main interactive loop stopped invoking `Agent.prompt()` before `readLine`.
- If a user sees only the startup `codegraff · folder: ...` banner but not per-turn `[model · cwd ...] ›`, that is exactly what the current control flow predicts.
